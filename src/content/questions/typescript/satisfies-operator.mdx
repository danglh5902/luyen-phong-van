## Ví dụ

<Runnable client:visible lang="ts" code={`type Color = "red" | "green";

const palette = {
  red: [255, 0, 0],
  green: "#0f0",
} satisfies Record<Color, string | number[]>;

// palette.red vẫn là number[] nên .map hợp lệ; palette.green là string
console.log(palette.red.map((n) => n / 255));
console.log(palette.green.toUpperCase());

// Với annotation: palette.red có kiểu string | number[], .map sẽ lỗi
// Với satisfies: gõ sai key (vd. "blue") hoặc thiếu key sẽ báo lỗi ngay`} />

| | Kiểm tra | Kiểu kết quả |
|---|---|---|
| `const x: T = v` | có | T (rộng) |
| `v as T` | lỏng, bỏ qua nhiều lỗi | T |
| `v satisfies T` | có (cả excess property) | kiểu suy luận của `v` |

<Callout type="tip">
Kết hợp `as const satisfies T` để vừa readonly/literal vừa được kiểm tra, thường dùng cho config, routes, bảng i18n.
</Callout>

<Callout type="pitfall">
`as T` có thể che giấu lỗi (`{} as User` biên dịch được). Ưu tiên `satisfies` hoặc annotation, chỉ dùng `as` khi bạn biết nhiều hơn compiler và có lý do rõ ràng.
</Callout>
